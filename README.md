## Задание 3

Токен `*` применяется в трёх контекстах:

1. В объявлении указателя — `int *p`.
2. При разыменовании указателя — `*p`.
3. Как оператор умножения — `a * b`.

Токен `&` также можно использовать тремя способами:

1. Как оператор взятия адреса — `&a`.
2. В объявлении ссылки — `int &r`.
3. Как побитовый оператор И — `a & b`.

```cpp
#include <iostream>

int main() {
    int a = 6;
    int b = 3;

    int *p = &a;       // * — объявление указателя, & — получение адреса
    int &r = a;        // & — объявление ссылки

    std::cout << *p << '\n';  // * — разыменование
    std::cout << a * b << '\n'; // * — умножение
    std::cout << (a & b) << '\n'; // & — побитовое И

    r = 10;
    std::cout << a << '\n'; // ссылка r — другое имя переменной a

    return 0;
}
```

## Задание 6

```cpp
double x = 0;
double *d = &x;
std::cout << reinterpret_cast<std::uintptr_t>(d + 4)
          - reinterpret_cast<std::uintptr_t>(d - 4) << '\n';
```

При арифметике указателей прибавление `4` означает смещение на четыре элемента типа `double`, а вычитание `4` — на четыре элемента назад. Разница между полученными адресами равна восьми размерам `double`.

Так как `sizeof(double) == 8`, арифметическая разница адресов — `8 * 8 = 64` байта.

Для другого типа величина шага меняется:

- `int`: `8 * 4 = 32` байта;
- `char`: `8 * 1 = 8` байт.

## Дополнительное задание 2

### Рассмотрим несколько вариантов:

```cpp
x[0][10] = 1;
```

Индекс столбца выходит за границы первой строки. С точки зрения стандарта C++ это неопределённое поведение. На распространённых реализациях адрес `x[0][10]` может совпасть с адресом `x[1][0]`, поскольку строки лежат в памяти подряд. Поэтому запись иногда выглядит так, будто она изменила первый элемент второй строки. Но рассчитывать на это нельзя. Вызывает предупреждение. Выводит `123`

```cpp
*(*(x + 0) + 10) = 2;
```

Это другая запись того же обращения: сначала выбирается первая строка, затем указатель смещается за её границу и разыменовывается. Результат также не определён стандартом. Предупреждения не вызывает. Выводит `123`

```cpp
*(x[0] + 10);
```

Это очередная запись того же обращения: сначала выбирается первая строка, затем указатель смещается за её границу и разыменовывается. Результат тоже не определён стандартом. Предупреждения не вызывает. Выводит `123`

```c++
*(x + 10)[0] = 123;
x[10][0] = 123;
*(*(x + 10) + 0) = 123;
*(x[10] + 0) = 123;
```

Аналогично с выходом за границы по строкам.

### Что происходит на уровне железа

Процессор обычно выполняет обращение к памяти по вычисленному адресу. Обычный указатель C++ не хранит информацию о размере массива, его строках и допустимых индексах. Поэтому процессор сам по себе, как правило, не проверяет, что индекс находится в диапазоне от 0 до 9.

Упрощённо возможны следующие ситуации:

1. **Адрес попал в доступную область памяти.** Процессор выполняет чтение или запись. Если там расположены другие данные программы, ошибочная запись может их повредить. Именно поэтому выход за границу иногда не приводит к заметной ошибке.
2. **Адрес попал в недоступную область виртуальной памяти.** Механизмы управления памятью процессора и ОС могут вызвать исключение доступа к памяти. ОС обычно завершает программу с ошибкой, например с сообщением о segmentation fault.
3. **Ошибка затронула данные, которые программа использует позднее.** Сбой может проявиться не в момент неправильной записи, а значительно позже: изменится результат вычислений, нарушится работа цикла или повредится служебное состояние программы.
4. **Компилятор использовал предположение об отсутствии неопределённого поведения.** Оптимизатор вправе преобразовать программу, исходя из того, что корректная программа не выходит за границы массива. Поэтому фактический результат может отличаться от простого ожидания «процессор записал число по соседнему адресу».

Аппаратная защита памяти обычно работает на уровне страниц виртуальной памяти и прав доступа, а не отдельных элементов C++ массива. Если ошибочный адрес находится на той же доступной странице, что и корректные данные, система может не заметить нарушения границ массива. Если адрес попадает на незамапленную страницу или страницу без нужных прав, обращение может вызвать аппаратное исключение.

**Вывод:** выход за границу массива — ошибка на уровне языка C++, даже если вычисленный адрес физически соответствует соседнему элементу и программа не падает. Железо обычно проверяет доступность области памяти, а не границы конкретного массива. Поэтому внешне успешное выполнение не делает такое обращение безопасным.

## Дополнительное задание 4

### 1. Выделение и освобождение динамической памяти

Оператор `new` выделяет память и возвращает указатель на созданный объект. Для освобождения памяти, выделенной через `new`, используется `delete`; для массива, выделенного через `new[]`, — `delete[]`.

```cpp
#include <iostream>

int main() {
    int *p = new int(42);
    std::cout << *p << '\n';
    delete p;
    p = nullptr;

    int *a = new int[5]{1, 2, 3, 4, 5};

    for (int i = 0; i < 5; ++i) {
        std::cout << a[i] << ' ';
    }
    std::cout << '\n';

    delete[] a;
    a = nullptr;

    return 0;
}
```

После освобождения памяти указатель больше нельзя разыменовывать. Присваивание `nullptr` помогает явно отметить, что он больше не указывает на действующий объект.

### 2. Что происходит при расширении массива

Обычный динамический массив, созданный через `new[]`, нельзя просто увеличить на месте. Для увеличения размера выделяют новый блок памяти, копируют элементы и освобождают старый блок.

```cpp
#include <iostream>

int main() {
    int oldSize = 3;
    int *data = new int[oldSize]{10, 20, 30};

    int newSize = 6;
    int *bigger = new int[newSize];

    for (int i = 0; i < oldSize; ++i)
        bigger[i] = data[i];

    for (int i = oldSize; i < newSize; ++i)
        bigger[i] = 0;

    delete[] data;
    data = bigger;
    bigger = nullptr;

    for (int i = 0; i < newSize; ++i)
        std::cout << data[i] << ' ';

    std::cout << '\n';

    delete[] data;

    return 0;
}
```

После расширения `data` указывает на новый блок. Старый адрес больше использовать нельзя. В частности, все копии старого указателя становятся недействительными.

### 3. Перемещение хранилища `std::vector`

`std::vector` самостоятельно управляет динамической памятью. Когда текущей вместимости (`capacity`) не хватает, контейнер выделяет более крупный блок и переносит туда элементы. Поэтому адреса элементов могут измениться, а ранее сохранённые указатели и ссылки — стать недействительными.

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {10, 20, 30};

    v.reserve(v.capacity() + 1); // Запрашиваем вместимость больше текущей

    int *saved = &v[0];
    std::cout << "До расширения: " << static_cast<const void*>(saved) << '\n';

    v.reserve(v.capacity() + 1); // Повторный запрос большей вместимости
    std::cout << "После расширения: "
              << static_cast<const void*>(v.data()) << '\n';

    std::cout << "Первый элемент: " << v[0] << '\n';
}
```

`reserve` запрашивает вместимость не меньше указанной. Если новая вместимость больше старой, перевыделение хранилища происходит, и указатели на прежние элементы инвалидируются. После перевыделения нужно пользоваться `v.data()` или заново получать адрес элемента, а не разыменовывать сохранённый ранее `saved`.
